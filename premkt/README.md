# premkt — 盘前动量选股

盘前 gap + 成交量数据（moomoo OpenD）与新闻催化剂（SEC EDGAR 8-K + moomoo 资讯）
结合的动量扫描器，输出带入场/止损/仓位的候选清单，并附一套前向验证工具。

## 核心论点

**盘前大涨本身不是 alpha，它更接近一个陷阱。** 实测样本（2026-08-07）：

| 标的 | 盘前 | 催化剂 | 收盘 | 从盘前价的日内变化 |
|---|---|---|---|---|
| DOCS | +89.6% | 财报超预期（8-K 2.02） | +32.6% | **−29.5%** |
| MB | +278.7% | 无（"limited fresh news"） | +137.9% | −37% |
| FIGS | +35.3% | 财报 + 上调指引 | +26.9% | −6% |

极端 gap 在开盘那一刻已经把消息完全 price in，日内是净卖压。真正可交易的边缘在于
把**有燃料的 gap** 和**下面是空气的 gap** 分开。

因此本策略里催化剂不是加分项，而是**乘数门控**：

```
base  = Σ weight_i × factor_i          # gap质量 / RVOL / 技术位 / 流通盘 / 流动性
score = 100 × base × catalyst_mult     # hard 1.15 · soft 1.00 · none 0.55 · negative 0.15
```

低流通盘 + 高 RVOL + 无消息，各分项都很漂亮 —— 用加分项会被其他维度平均掉，
用乘数不会。

## 五个打分维度

| 维度 | 权重 | 逻辑 |
|---|---|---|
| gap 质量 | 0.22 | 对数正态曲线，峰值 12%。不是越大越好，>40% 快速衰减 |
| 盘前 $RVOL | 0.30 | 盘前成交额 ÷ 20 日平均日成交额。最强的单一预测因子 |
| 技术位 | 0.20 | 相对 52 周极值与 MA20 的位置，衡量路径上剩多少反向筹码 |
| 流通盘/融券 | 0.14 | 做多是逼空燃料；做空是被轧风险，**符号相反** |
| 流动性 | 0.14 | 点差 + 名义成交额，决定滑点和容量 |

技术位和流通盘两项对多空的解读是镜像的 —— 52 周低位对做多是套牢区，
对做空是无支撑的下降趋势；7M 流通盘的难借票是做空爆仓的经典路径。

## 催化剂：重要性与方向分开

这是设计上最关键的一处区分。

- **重要性（materiality）**：方向中性。8-K item 2.02 只说明"公司披露了业绩"，
  并没有说业绩好坏 —— 涨还是跌由 gap 本身告诉你。把它当利好用，做空侧就会把
  "财报暴雷跌 27%" 错判成反向信号。
- **方向（direction）**：自带符号。增发/退市/破产对做多是利空，对做空恰恰是最好的催化剂。

两条独立证据链：

1. **SEC EDGAR 8-K** — 免费、无需 key、带结构化 item 代码和精确到秒的
   `acceptanceDateTime`。这是"公司自己在法律文件里承认这事重大"的证据，
   比标题关键词可靠得多。
2. **moomoo `get_search_news`** — Benzinga / GlobeNewswire / MT Newswires 等标题，
   用正负词典打分。

负面词典是这里最值钱的部分：小盘股盘前暴涨最常见的真实原因是**宣布增发**，
那是做空信号而不是做多信号。同理，8-K 里 `1.01 + 3.02 + 3.03 + 5.03` 是定增融资的
典型组合，此时 1.01 指的就是证券购买协议本身，不能按"重大协议"当利好
（实盘上 HCWC 就是这么被误判的，已有回归测试覆盖）。

## 用法

```bash
python -m premkt.scan                      # 做多候选 top 15
python -m premkt.scan --side both          # 同时给做空候选
python -m premkt.scan --top 25 --details 8 # 更多候选 + 更详细的交易计划
python -m premkt.scan --no-news            # 跳过催化剂查询（快速预览）
python -m premkt.scan --account 250000 --risk 0.75   # 按自己的账户算仓位
python -m premkt.scan --save               # 存快照，供收盘后前向验证
```

**运行时机：美东 08:00–09:15**（盘前流动性起来之后、开盘之前）。

### 数据新鲜度陷阱（重要）

`pre_*` 字段与盘前榜在**美东 04:00 之前不会翻到新的一天**。凌晨 2 点跑扫描，
拿到的是上一个交易日的盘前数据，而且 `update_time` 照常刷新、所有字段外观完全正常
—— 这是最危险的一类脏数据。

程序做了两道防护：

1. 时段判断：04:00 ET 前标记为 `overnight` 并红字警告
2. 数据交叉校验：快照的 `prev_close_price` 应当等于最近一根已完成日线的收盘，
   对不上就说明数据陈旧，此时 `--save` 会被自动禁用（避免污染验证样本）

催化剂的时间窗也锚定"盘前数据所属的交易日"而不是墙上时钟，否则真正的催化剂新闻
会被 36 小时窗口整个滤掉。

## 前向验证

**为什么没有常规回测**：Futu OpenAPI 不保留历史盘前快照，`get_us_pre_market_rank`
只有"当前"这一期。没有办法回溯生成历史候选池 —— 任何声称回测过盘前 gap 策略的东西，
要么用了别的数据源，要么在用当日全量数据反推，那是前视偏差。

替代方案是逐日累积样本：

```bash
# 每个交易日盘前
python -m premkt.scan --save

# 收盘后（用当天真实分钟线兑现每一条交易计划）
python -m premkt.evaluate
python -m premkt.evaluate --date 2026-08-11 --csv out.csv
python -m premkt.evaluate --dir premkt/snapshots/dryrun   # 看内置的演练样本
```

评估器用 1 分钟线按时间顺序兑现：先判断是否触发入场，再看止损和目标谁先到
（同一根 K 线内双触时保守判止损）。输出按催化剂分组的对照，直接检验核心假设。

内置演练样本（2026-08-07，n=28，**统计上不足以下结论**，只用于验证工具链）：

```
catalyst  笔数  平均开→收%  平均R   胜率%
hard        24    -2.28    0.26   58.33
soft         2     1.11    0.39   50.00
none         2   -11.59   -0.19   50.00
触发率 16/28 (57%)   评分 vs 开→收 Spearman +0.344
```

方向符合假设（hard 组显著好于 none 组），但 n=28 且集中在同一天的财报季，
**需要累积 100 笔以上再回过头调 `config.py` 里的权重**。

注意演练样本有一处已知的轻微前视：moomoo 对隔日新闻只给到"月/日"精度，
同一天内的先后无法区分。实盘在 08:00 ET 跑时这不是问题（当天的新闻本来就是盘前新闻）。

## 交易计划

- **入场**：突破盘前高（做空则跌破盘前低）
- **止损**：盘前极值与 `1×ATR14` 中较紧的那个；超过 8% 标记"止损过宽"
- **仓位**：`账户 × 单笔风险% ÷ 每股风险`，默认 $100k × 0.5%
- **目标**：1R / 2R / 3R

演练样本里 43% 的标的从未触发入场 —— 这是突破式入场的固有特征，不是 bug。
DOCS 盘前 +89.6% 开盘后一路跌 −29.5%，正是因为没能突破盘前高而躲过。

## 盘中版：动量 + 买量双升

`scan.py` 是盘前工具（只有 gap 和盘前成交额）。开盘后用 `intraday.py`，
它能看到 VWAP、日内位置和逐分钟资金流曲线 —— 后者才回答得了
"买量是不是**还在**上升"，而不只是"今天量大"。

```bash
python -m premkt.intraday                    # top 15
python -m premkt.intraday --news             # 附带催化剂（会慢 ~40s，值得）
python -m premkt.intraday --min-change 5 --min-turnover 20000000
python -m premkt.intraday --fast             # 跳过资金流，只看量比+VWAP
```

**"同时上升"是硬要求**，所以总分用几何平均而不是加权和：

```
score = 100 × √(动量分 × 买量分) × 流动性调整
```

加权和允许一头补另一头（量暴增但价在跌，或价猛涨但无量），几何平均不允许。
此外还有两道硬门槛：站上当日 VWAP + 日内位置 ≥55%（动量），
主力净流入为正 + 近 30 分钟净流入斜率 > 0（买量）。后者不满足的会被
单独列到"涨势尚在但资金已转流出"分区。

- **动量** = 涨幅（对数正态曲线，峰值 8%）+ 日内区间位置 + 相对 VWAP 溢价
- **买量** = 量比 + 主力净占（特大单+大单净买入占比）+ 净流入斜率 + 买卖盘比

## OpenD 接口坑（实测，都会静默降级）

| 接口 | 坑 |
|---|---|
| `get_search_news` | 限频 **10 次/30 秒**，超限返回错误而非空结果。不节流又吞异常 = 大部分票显示"无新闻"，丢的恰好是抓增发的方向信号 |
| `get_stock_filter` | 限频 10 次/30 秒；US 市场只支持 `CUR_PRICE`/`MARKET_VAL`/`VOLUME_RATIO`/`CHANGE_RATE_5MIN`，`CHANGE_RATE`/`TURNOVER`/`VOLUME` 都不支持 |
| `get_market_snapshot` | **没有 `change_rate` 字段**，今日涨幅要用 `last_price/prev_close_price` 自己算；`avg_price` 才是当日 VWAP |
| `get_market_snapshot` | 批量里只要有一个无行情权限的代码（如 OTC 的 STRS），**整批一起失败** —— 已用二分拆批跳过 |


## 已知限制

- 盘前数据只在 04:00 ET 后有效，程序会拦截但无法凭空造出数据
- `get_search_news` 按公司名搜索，冷门票可能搜不到；EDGAR 是主要证据链
- 关键词词典是英文的，覆盖不了所有表述方式；漏判会落到 `none`（乘数 0.55）而不是误判
- 权重目前是先验设定的，没有经过样本外拟合 —— 这正是 `evaluate` 存在的意义
- 不含实际下单，只输出候选和计划
